# A7Z OpenWrt Integration Status

## Current state

The repository has three separate build paths:

- OpenWrt 24.10 with Linux 6.6 is the established CI baseline; A7Z produced a successful artifact in run `44216787167`.
- OpenWrt 24.10 with Linux 6.18 builds for both A7Z and A7A (run `44622092813`). Getting there took a series of fixes; each 6.6-era BSP assumption that breaks under Linux 6.12 and later was found one build stage at a time:
  1. The BSP `choice` blocks declared `tristate` members, which Linux 6.12/6.18 kconfig rejects with `error: choice member must be bool` (6.6 and 5.15 kconfig never checked this). `AW_MTD_SPI_NOR_5_15`, `AW_MTD_SPI_NOR_6_1`, `AW_PCIE_RC`, `AW_PCIE_EP` and `AW_PCIE_NONE` are now `bool` (`openwrt-sunxi-aiot` `518b7815`); no config used `=m` for them.
  2. kconfig also dropped the `optional` choice keyword (absent from the v6.18 `scripts/kconfig/lexer.l` token set) and resolves `bsp/drivers/cpufreq/Kconfig`'s `$(VERSION).$(PATCHLEVEL)` source to a `cpufreq-linux-6.18/` directory the BSP never shipped, so `syncconfig` aborted with `bsp/drivers/mtd/Kconfig:106: syntax error` and `bsp/drivers/cpufreq/Kconfig:3: can't open file "bsp/drivers/cpufreq/cpufreq-linux-6.18/Kconfig"` (runs `44370384451`, `44370392220`). Both are fixed in `openwrt-sunxi-aiot` `ca77f337`: the sole `optional` line is removed and `cpufreq-linux-6.18/` is a verbatim copy of `cpufreq-linux-6.6/` with its `source` updated; `CONFIG_AW_CPUFREQ_DT` stays off in `config-6.18`, so nothing from that copy is compiled until the driver is rebased onto the 6.18 OPP/cpufreq API.
  3. OpenWrt's gcc toolchain carries `imply KERNEL_WERROR` on `GCC_USE_DEFAULT_VERSION` (`toolchain/gcc/Config.version:24`), so the build system .config ends up with `CONFIG_KERNEL_WERROR=y` even though every kernel config fragment says `# CONFIG_WERROR is not set`. `package-metadata.pl kconfig` turns that into a kernel `CONFIG_WERROR=y`, and the 6.18 tree then compiles with `-Werror` applied to the warnings v6.18 enables by default (`scripts/Makefile.extrawarn:11-22`: `-Wextra`, `-Wmissing-declarations`, `-Wmissing-prototypes`), none of which 6.6 enables. The first hit was `bsp/drivers/clk/sunxi-ng/ccu_common.c:401:5: error: no previous prototype for 'ccu_is_sdm_enabled' [-Werror=missing-prototypes]` in runs `44438652577` and `44438675936`. Both workflow `.config` heredocs now set `# CONFIG_KERNEL_WERROR is not set`, which overrides the imply.
  4. With kconfig, DTC and `-Werror` resolved, the build reached real compile errors from APIs that changed after 6.6 (`openwrt-sunxi-aiot` `ab224582`): Linux 6.18 moved the syscore registration node into `struct syscore` and gave its callbacks a `void *data` argument, so `register_syscore_ops()` no longer exists and `bsp/drivers/clk/sunxi-ng/ccu_common.c:229/230/254` failed with `incompatible pointer type` and `implicit declaration of function 'register_syscore_ops'` (runs `44510599631`, `44510607164`). `bsp/include/sunxi-syscore.h` keeps the argument-less BSP callbacks and wraps them for either API through `sunxi_register_syscore()`/`sunxi_unregister_syscore()`; the five users are `ccu_common.c`, `ccu-displl.c`, `clk-sun8iw21.c`, `irq-sun8i-nmi.c` and `dump_reg.c`. The same commit adapts `pinctrl-sunxi.c` and `pinctrl-axp22x.c` to the 6.7 `pinctrl_gpio_direction_input/output(chip, offset)` form and the 6.17 `gpio_chip->set` returning `int` (`pinctrl-sunxi.c:2569`), gives `ccu-sunxi-rtc.c` the `linux/platform_device.h` include it always missed plus a 6.13-style `void remove` callback, and silences the 6.18-only `-Wmissing-prototypes`/`-Wmissing-declarations`/`-Wextra` stylistic warnings for the whole BSP subtree with `subdir-ccflags-y` in `bsp/Makefile` (the BSP has thousands of prototype-less helpers; `KBUILD_CFLAGS` would only affect the top level, `scripts/Makefile.build:42` is what propagates `subdir-ccflags-y`).
  5. Once kconfig, DTC and the warning set were resolved the compiler hit callbacks whose signatures changed after 6.6. `struct platform_driver.remove` takes `void` from Linux 6.11 and `remove_new` disappeared in 6.13, but 239 BSP files still returned `int`; `openwrt-sunxi-aiot` `9c534aa0` converts them and routes every initialiser through `SUNXI_PLATFORM_REMOVE()` in `bsp/include/sunxi-platform.h`, which expands to `.remove` on 6.11+ and `.remove_new` on older kernels. `struct i2c_driver` and `struct spi_driver` have always taken `void`, yet 119 sensor, VFE, actuator and codec callbacks returned `int`; `1caca912` fixes those plus the `aw_hdmi_drv_remove` platform callback the first pass missed. Linux 6.12 also dropped the transitive `linux/platform_device.h` include from `of_device.h` and `of_platform.h`, so `7b1533b5` adds the explicit include to 101 BSP sources.
  6. Linux 6.10 removed `struct circ_buf xmit` from `struct uart_state` and moved the transmit buffer into `struct tty_port` as an `xmit_fifo` kfifo, dropping `uart_circ_empty()`, `uart_circ_chars_pending()` and `SERIAL_CIRC_CNT_TO_END()` with it. The build then failed in `bsp/drivers/uart/sunxi-uart.c:332/335/347/379-381/389` with `error: 'struct uart_state' has no member named 'xmit'`, `implicit declaration of function 'uart_circ_empty'` and `invalid use of undefined type 'struct circ_buf'`, identically in the 25.12 workflow and in the 6.18 workflow (run `44553705447`, `44553715646`). `openwrt-sunxi-aiot` `b696182d` adds `bsp/drivers/uart/sunxi-uart-compat.h`, whose `sunxi_uart_tx_pending/empty/peek/advance()` helpers wrap `kfifo_len()`/`kfifo_is_empty()`/`kfifo_peek()`/`uart_xmit_advance()` on 6.10+ and keep the `circ_buf` form before that, and rewrites the PIO transmit loops of `sunxi-uart.c` and `sunxi-uart-ng-core.c` plus the TX helpers of `sunxi-uart-ng-dma.c` in terms of them. The DMA transmit path aliased `xmit.buf` with its bounce buffer, which is impossible once the tty core owns the kfifo, so `dma_tx_callback`/`sunxi_uart_start_dma_tx` are stubbed out behind `SUNXI_UART_XMIT_DMA_ALIAS` on 6.10+ and the driver falls back to PIO (`AW_SERIAL_DMA` was never enabled on 6.6 either). `config-6.18` additionally selects `CONFIG_AW_UART_NG=y` with `# CONFIG_AW_UART is not set`, `CONFIG_AW_UART_DYNAMIC_DEBUG=y` and `CONFIG_AW_SERIAL_CONSOLE=y`, mirroring `aiot/config-6.6`; the device trees need that anyway because `sun60iw2p1.dtsi` uses `compatible = "allwinner,uart-v100"`, which only `sunxi-uart-ng-core.c` matches.
  7. With every compile error gone the build reached the vmlinux link and failed with 34 `multiple definition` errors: `bsp/drivers/clk/sunxi-ng/ccu_div.o:...: multiple definition of `ccu_div_ops'; drivers/clk/sunxi-ng/ccu_div.o:...: first defined here`, and the same for `ccu_gate_ops`, `ccu_mult_ops`, `ccu_mux_ops`, `ccu_reset_ops`, `ccu_mp_ops`, `ccu_mp_mmc_ops`, `ccu_nk_ops`, `ccu_nkm_ops`, `ccu_nkmp_ops`, `ccu_nm_ops`, `ccu_phase_ops`, the `ccu_frac_helper_*`, `ccu_gate_helper_*`, `ccu_mux_helper_*`, `ccu_sdm_helper_*` helpers, `ccu_helper_wait_for_lock`, `ccu_mux_notifier_register` and `ccu_pll_notifier_register` (runs `44614713336`, `44614726999`). `drivers/clk/sunxi-ng/Kconfig` sets `config SUNXI_CCU ... default ARCH_SUNXI`, so the mainline clock framework was compiled alongside the BSP's own copy under `bsp/drivers/clk/sunxi-ng/`, and both define the same globals; nothing complains until the two objects are linked into `vmlinux.o`. `config-6.18` now carries `# CONFIG_SUNXI_CCU is not set` (`openwrt-sunxi-aiot` `d0156057`), matching `aiot/config-6.6:1293`, which has always disabled it.
  8. **modpost: `irq_to_desc` is not exported on arm64.** Run `44622062727` (25.12) got past
     `vmlinux.o` linking once the duplicate `ccu_*` symbols were gone, then failed with
     `ERROR: modpost: "irq_to_desc" [bsp/drivers/input/init-input.ko] undefined!`.
     `kernel/irq/irqdesc.c` only exports `irq_to_desc()` in the `!CONFIG_SPARSE_IRQ` branch
     (`EXPORT_SYMBOL(irq_to_desc)`); under `CONFIG_SPARSE_IRQ` the export sits inside
     `CONFIG_KVM_BOOK3S_64_HV_MODULE`, and `arch/arm64/Kconfig` selects `SPARSE_IRQ`
     unconditionally (v6.6.60 `:251`, v6.18.60 `:274`), so the symbol is never visible to modules.
     The 24.10 trees never hit this because their config fragments leave `CONFIG_INPUT` off, which
     keeps `AW_INPUT_SENSORINIT` (default `m`, depends on `INPUT`) unbuilt; the 25.12 tree turns
     `CONFIG_INPUT` on through `target/linux/sunxi/config-6.12:251`.
     `5fe1e803` drops `irq_to_desc()` from `bsp/drivers/input/init-input.c` (and the debug print in
     `bsp/drivers/input/ctp/nvt36xxx/nt36xxx.c`) in favour of the exported `irq_get_irq_data()` plus
     `irqd_irq_disabled()`, which works on both sparse and non-sparse kernels.
  9. **The 25.12 tree links the mainline MMC host against the symbols item 7 removed.**
     Run `44632381089` got past the `ccu_*` duplicates and failed at `vmlinux.o` with
     `drivers/mmc/host/sunxi-mmc.c:795/1406: undefined reference to sunxi_ccu_set_mmc_timing_mode`
     and `:1409: undefined reference to sunxi_ccu_get_mmc_timing_mode`. Those two symbols live in
     `drivers/clk/sunxi-ng/ccu_mmc_timing.c`, part of the `sunxi-ccu-y` aggregate, so
     `# CONFIG_SUNXI_CCU is not set` removed them while the mainline MMC host still called them.
     That driver was compiled because `target/linux/sunxi/config-6.12:313` sets
     `CONFIG_MMC_SUNXI=y` and `patches-6.18/0001-allwinner-a733-orangepi-4-pro-6.18-mainline.patch`
     relaxes its dependency to `depends on SUNXI_CCU || AW_CCU`, which `AW_CCU=y` satisfies.
     Building it is pointless anyway: its `of_match` table does not list
     `allwinner,sunxi-mmc-v4p6x`, the compatible `sun60iw2p1.dtsi:4338` uses, so it could never bind.
     `config-6.18` now turns `CONFIG_MMC` and `CONFIG_MMC_BLOCK` on (the generic 6.18 fragment leaves
     them off), disables `CONFIG_MMC_SUNXI`, and builds the BSP host instead: `CONFIG_AW_MMC=y` with
     `AW_MMC_V4P00X/V4P1X/V4P5X/V5P3X=y` and `CONFIG_AW_MMC_HSQ=y` (needed because `AW_MMC` depends on
     `MMC_HSQ || AW_MMC_HSQ` and the generic fragment disables `MMC_HSQ`), mirroring
     `aiot/config-6.6:237-244` and `:844-847` (`openwrt-sunxi-aiot` `df9ef9cf`). The same commit fixes
     `bsp/drivers/mmc/sunxi-mmc.c:2996`, which called `mmc_card_blockaddr()`; no kernel release ever
     shipped that name, the helper is `mmc_card_is_blockaddr()`. Note that the green 6.18 image above
     was built before this change and therefore carries no MMC host at all
     (`CC drivers/mmc/...` never appears in its build log), so an SD/eMMC root mount is not
     possible with it.

## Integrated pieces

1. The active 24.10 source contains the A7Z profile, Allwinner BSP overlay, A7Z/SoC DTS files, vendor image helper, extlinux configuration and prebuilt U-Boot files.
2. The 6.18 kernel config selects known Sun60IW2 BSP Kconfig symbols. It no longer contains the earlier invalid OpenWrt package selector `CONFIG_KMOD_CEDAR_VPU`; Cedar VPU availability is still unverified.
3. `scripts/apply-openwrt-25.12-overlay.sh` prepares the pinned 25.12 source without modifying the upstream submodule commit, copies the AIoT fork's `backport-6.18`, `hack-6.18` and `pending-6.18` patch sets plus `config-6.18`/`kernel-6.18` metadata into it, and applies parent-repo patches for device image generation, the DTS registration, virtual dependency handling and the `nf-flow` module dependency.
4. The independent workflows build OpenWrt 24.10/Linux 6.6, OpenWrt 24.10/Linux 6.18 (A7A/A7Z), and OpenWrt 25.12/Linux 6.18 (A7Z), with build logs and artifacts uploaded for diagnosis.
